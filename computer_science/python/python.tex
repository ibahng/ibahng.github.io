\section{Introduction to Python}

  \begin{core}{Python 3.0}

    Following several major releases over preceding decades (\textit{Python 0.9.0 in February 1991, Python 1.0 in January 1994, Python 2.0 in October 2000}), Python 3.0 was released in December 2008 and has since evolved through incremental updates to Python 3.14.5 as of May 10, 2026.

    The largest and most impactful version change came with the \textbf{transition from Python 2 to Python 3}, requiring over a decade for a complete migration due to \textbf{deliberate backward incompatibility}. This breaking change made many developers hesitant to migrate given the substantial time and cost involved in a complete update to Python 3 syntax and logic in existing codebases.

    \textit{Today, Python 3 represents the definitive global industry standard for development, while Python 2 is structurally obsolete. Python 2 officially reached its End-of-Life (EOL) on January 1, 2020, and no longer receives security patches, bug fixes, or official maintenance.}

  \end{core}

  \begin{core}[label=core:cpython]{CPython vs Jython vs PyPy}

    The original Python interpreter was implemented in \textbf{C}, a lower-level language positioned above \textbf{assembly} and \textbf{machine code}. This C-based implementation, known as \textbf{CPython}, remains the standard reference version distributed via \href{https://www.python.org/}{python.org}.

    Alternative implementations include \textbf{Jython}, built on Java for seamless Java ecosystem integration, and \textbf{PyPy}, which offers significantly faster execution for pure Python code. However, Jython remains limited to Python 2.7 compatibility, while PyPy exhibits reduced compatibility with C-based libraries (\textit{\autoref{core:libraries}}), many of which are essential to major projects.

  \end{core}

\section{Data Types \& Structures}

  \subsection{Singular Data Types}

    \begin{core}{Numerics}

      \textbf{Numeric data types} encompass the set of data representations used to encode quantitative values within Python. Python provides several built-in numeric forms, each made for different purposes.

      \begin{pyconsole}

        a,b,c,d = 10, 0b1010, 0o12, 0x0a
        print(a, b, c, d)
        print(type(a), type(b), type(c), type(d))

        print(type(3.14))

        print(type(2 + 5j))

      \end{pyconsole}
      \pcon{Numeric data types \textcode{int}, \textcode{float}, and \textcode{complex}}{code:numerics}

      \begin{enumerate}

        \item \textcode{int}: Integers represent whole numbers without a fractional component. They may be positive, negative, or zero. For example, the values \textcode{7}, \textcode{-42}, and \textcode{0} are all classified as integers in Python.
        
        Integers can also be represented in \textbf{binary} (\textit{base-2}), \textbf{octal} (\textit{base-8}), or \textbf{hexadecimal} (\textit{base-16}) notation using the prefixes \textcode{0b}, \textcode{0o}, and \textcode{0x}, respectively. For instance, \textcode{0b1010}, \textcode{0o12}, and \textcode{0x0a} all correspond to the decimal integer value \textcode{10}.

        \item \textcode{float}: Floats represent real numbers containing decimal components. For instance, \textcode{3.14} and \textcode{-0.001} are floating-point values commonly used to represent continuous numerical quantities.

        \item \textcode{complex}: Complex numbers represent values composed of both real and imaginary components in the form \textcode{a + bi}, where \textcode{i} denotes the imaginary unit satisfying \textcode{i$^2$ = -1}. As an example, the expression \textcode{2 + 5j} represents a complex number, where \textcode{j} denotes the imaginary component.

      \end{enumerate}

    \end{core}

    \begin{core}[label=core:boolean]{Boolean}

      \textcode{bool} represents logical truth values consisting exclusively of \textcode{True} or \textcode{False}. They are primarily used in conditional expressions, logical operations, and program control flow. For example, the expression \textcode{5 > 3} evaluates to \textcode{True}, whereas \textcode{5 < 3} evaluates to \textcode{False}.

      \begin{pyconsole}

        print(type(True), type(False))

      \end{pyconsole}
      \pcon{\textcode{bool} data type}{code:bool}

    \end{core}

    \begin{core}{None}

      \textcode{NoneType} data type represents the \textbf{absence} of a value or the \textbf{intentional lack} of an assigned object. Python provides the singleton value \textcode{None} to denote null or undefined states within a program. 

      \begin{pyconsole}

        print(type(None))

      \end{pyconsole}
      \pcon{\textcode{None} data type}{code:none}

    \end{core}

    \subsubsection{Strings}

      \begin{core}[label=core:string]{String}

        The \textcode{str} data type is an ordered sequence of textual characters surrounded by quotation marks, serving as the fundamental data type for text. For example, \textcode{"hello world"} constitutes a string literal. String objects support a variety of methods and operations for transformation and analysis.

        \begin{pyconsole}

          print(type("hello world"))

        \end{pyconsole}
        \pcon{\textcode{str} data types}{code:str}

        \begin{enumerate}

          \item \textbf{Indexing and Slicing}: Accesses individual characters at specified positions using zero-based numerical indices, or extracts contiguous subsequences by specifying start and end positions.

          \begin{pyconsole}

            example_string = "hello world"
            print(example_string[0])
            print(example_string[3:9])

          \end{pyconsole}
          \pcon{String indexing and slicing}{code:s_index}

          \item \textbf{Repetition}: Creates a new string by concatenating multiple copies of the original string.

          \begin{pyconsole}

            example_string = "hello world"
            print(example_string*2)

          \end{pyconsole}
          \pcon{String repetition}{code:s_rep}

          \item \textbf{Length}: \textcode{len()} returns the total number of characters contained within the string.

          \begin{pyconsole}

            example_string = "hello world"
            print(len(example_string))

          \end{pyconsole}
          \pcon{Retrieving string length through \textcode{len()}}{code:s_length}

          \item \textbf{Strip}: \textcode{.strip()} removes leading and trailing characters from the string. By default, \textcode{.strip()} removes whitespace.

          \begin{pyconsole}

            example_string = "   hello world   "
            print(example_string)
            stripped_string = example_string.strip()
            print(stripped_string)

          \end{pyconsole}
          \pcon{Removing leading and trailing whitespace from a string with \textcode{.strip()}}{code:s_strip}

          \item \textbf{Find}: \textcode{.find()} locates the first occurrence of a specified substring and returns its starting index position.

          \begin{pyconsole}

            example_string = "hello world"
            substring = "l"
            example_string.find(substring)

          \end{pyconsole}
          \pcon{Finding a substring within a string through \textcode{.find()}}{code:s_find}

          \item \textbf{Count}: \textcode{.count()} returns the number of non-overlapping occurrences of a specified substring within the string.

          \begin{pyconsole}

            example_string = "hello world"
            substring = "l"
            example_string.count(substring)

          \end{pyconsole}
          \pcon{Determining a substring count within a string using \textcode{.count()}}{code:s_count}

          \item \textbf{Upper/Lower/Title}: \textcode{.upper()}, \textcode{.lower()}, and \textcode{.title()} converts all characters to uppercase, lowercase, or title case (\textit{capitalizing the first letter of each word}), respectively.

          \begin{pyconsole}

            example_string = "hello world"
            print(example_string.upper())
            print(example_string.lower())
            print(example_string.title())

          \end{pyconsole}
          \pcon{Converting a string to upper, lower, and title case using \textcode{.upper()}, \textcode{.lower()}, and \textcode{.title()}}{code:s_ult}


          \item \textbf{Split}: \textcode{.split()} divides the string into a list of substrings based on a specified delimiter character or whitespace.

          \begin{pyconsole}

            example_string = "hello world this is an example string"
            print(example_string.split())

          \end{pyconsole}
          \pcon{Spliting a string into components using \textcode{.split()}}{code:s_split}

        \end{enumerate}

      \end{core}

      \begin{core}[label=core:escape_char]{Escape Characters}

        Certain special string character sequences begin with a backslash and represent non-printable or reserved characters. For instance, \textcode{\textbackslash n} for newline, \textcode{\textbackslash t} for tab, \textcode{\textbackslash\textbackslash} for the \textbackslash character, and \textcode{\"} for the " character.

        \begin{pyconsole}

          example_string = "hello world\n\nhello world\\ \t \""
          print(example_string)

        \end{pyconsole}
        \pcon{Special escape characters}{code:s_escape}

      \end{core}

      \begin{core}{String Types}

        Python provides several string literal prefixes that modify how the interpreter parses and stores the resulting object. The three primary prefixes are \textcode{f}, \textcode{r}, and \textcode{b}, which may also be combined in certain valid pairings.

        \begin{enumerate}

          \item \textcode{f}: \textbf{f-strings} allow arbitrary Python expressions to be embedded directly within a string literal by enclosing them in curly braces \textcode{\{\}}. Expressions are evaluated at runtime and their results interpolated into the surrounding string.

          \begin{pyconsole}

            name = "Ada"
            print(f"Hello, {name}!")
            print(f"Pi approx {3.14159:.2f}")
            print(f"{name=}")

          \end{pyconsole}
          \pcon{f-string demonstration}{code:f_string}

          \item \textcode{r}: \textbf{r-strings} instruct Python to treat every backslash (\textit{\autoref{core:escape_char}}) as a literal character rather than the start of an escape sequence.

          \begin{pyconsole}

            print("line1\nline2")
            print(r"line1\nline2")

          \end{pyconsole}
          \pcon{r-string demonstration}{code:r_string}

          \item \textcode{b}: \textbf{b-strings} produce a \textcode{bytes} object (\textit{\autoref{core:bytes}}) rather than a \textcode{str}. Each element must be an ASCII character or an escape sequence. This type is used extensively in binary file I/O, network communication, and low-level data processing.

          \begin{pyconsole}

            b = b"hello"
            print(type(b))
            print(b[0])

          \end{pyconsole}
          \pcon{b-string demonstration}{code:b_string}

        \end{enumerate}

        Prefixes can also be combined in order to use the functionality of multiple string types concurrently. The ordering of these prefixes is insignificant, meaning that the \textcode{rf} prefix is equivalent to the \textcode{fr} prefix. 

        Some commonly used combined string prefixes are \textcode{rf}---which is typically present in dynamic regex (\textit{\autoref{core:regex}}) patterns---and \textcode{rb}, which is used when the corresponding binary string includes literal backslashes.

        \begin{pyconsole}

          user_id = "dev_88"
          dynamic_path = rf"C:\Users\admin\desktop\{user_id}"
          print(f"Dynamic Path: {dynamic_path}")
          
          binary_regex_pattern = rb"FindThis\x00\x01"
          print(f"Raw Byte Pattern: {binary_regex_pattern}")

        \end{pyconsole}
        \pcon{String prefix combination \textcode{rf} and \textcode{rb}}{code:s_comb}

      \end{core}

      \begin{core}{String Formatting}

        % name = john
        % marks = 95.456
        % print("Name is",name,"Marks are",marks)
        % Name is john Marks are 95.456

      \end{core}

  \subsection{Sequence Data Types}

    \begin{core}{Lists}

      A \textcode{list} is an ordered, \textbf{mutable} (\textit{modifiable after creation}) sequence that can contain elements of any data type. Lists are defined using square brackets and support dynamic modification of their contents. For example, \textcode{[1, 2, 3, "hello"]} constitutes a list literal containing both integers and a string.

      \begin{enumerate}

        \item \textbf{Indexing and Slicing}: Accesses individual elements or subsequences using zero-based indices, analogous to string operations.

        \begin{pyconsole}

          example_list = [1, 2, 3, 4, 5]
          print(example_list[0])
          print(example_list[1:4])

        \end{pyconsole}
        \pcon{List indexing and slicing}{code:l_index}

        \item \textbf{Element Addition \& Removal}: \textcode{.append()} and \textcode{.insert()} both add a single element to the end of the list, modifying the list in place, but \textcode{.insert()} allows the addition to occur at a specified index position, shifting subsequent elements rightward. Conversely, \textcode{.remove()} deletes the first occurrence of a specified value from the list.

        \begin{pyconsole}

          example_list = [1, 2, 3]
          example_list.append(4) # append
          print(example_list)
          example_list.insert(2, 5) # inserting 3 at index 2
          print(example_list)
          example_list.remove(2) # removal
          print(example_list)

        \end{pyconsole}
        \pcon{List element addition through \textcode{.append()} / \textcode{.insert()} and removal through \textcode{.remove()}}{code:l_add_remove}

        \item \textbf{Sort}: \textcode{.sort()} Arranges list elements in a specified order, modifying the list in place. By default, \textcode{.sort()} arranges the list in ascending order.

        \begin{pyconsole}

          example_list = [3, 1, 4, 1, 5, 9]
          example_list.sort() # ascending order
          print(example_list)

        \end{pyconsole}
        \pcon{List sorting using \textcode{.sort()}}{code:l_sort}

        \item \textbf{Join}: \textcode{.join()} concatenates list elements into a single \textbf{string} using a specified delimiter.

        \begin{pyconsole}

          example_list = ["hello", "world", "example"]
          print(" ".join(example_list))

        \end{pyconsole}
        \pcon{Joining a list of strings using \textcode{.join()}}{code:l_join}

        \item \textbf{List Comprehension}: Constructs new lists using concise inline syntax that applies an expression to each element of an iterable (\textit{\autoref{core:for}}).

        \begin{pyconsole}

          numbers = [1, 2, 3, 4, 5]
          print([x*2 for x in numbers])

        \end{pyconsole}
        \pcon{List comprehension}{code:l_comp}

      \end{enumerate}

    \end{core}

    \begin{core}{Tuples}

      A \textcode{tuple} is an ordered, \textbf{immutable} (\textit{cannot be modified after creation}) sequence that can contain elements of any data type, making it suitable for fixed data structures that should not be modified. For example, \textcode{(1, 2, 3, "hello")} constitutes a tuple literal.

      \begin{enumerate}

        \item \textbf{Indexing and Slicing}: Accesses individual elements or subsequences using zero-based indices, identical to list operations.

        \begin{pyconsole}

          example_tuple = (1, 2, 3, 4, 5)
          print(example_tuple[0], example_tuple[1:4])

        \end{pyconsole}
        \pcon{Tuple indexing and slicing}{code:t_index}

        \item \textbf{Tuple Packing and Unpacking}: Assigns multiple values simultaneously or extracts tuple elements into separate variables.

        \begin{pyconsole}

          x,y = (10, 20)
          print(x)

        \end{pyconsole}
        \pcon{Tuple packing and unpacking}{code:t_pack_unpack}

      \end{enumerate}

    \end{core}

    \begin{core}{Sets}

      A \textcode{set} is an \textbf{unordered} collection of \textbf{unique} elements that support mathematical set operations. Defined using curly braces or the \textcode{set()} constructor, sets automatically \textbf{eliminate duplicate values}. For example, \textcode{\{1, 2, 3\}} constitutes a set literal.

      \begin{enumerate}

        \item \textbf{Element Addition \& Removal}: \textcode{.add()} and \textcode{.update()} inserts a single element or multiple elements, respectively into the set. Conversely, \textcode{.remove()} deletes a specified element, raising an error if the element does not exist.

        \begin{pyconsole}

          example_set = {1, 2, 3}

          example_set.add(4) # singular addition
          print(example_set)

          example_set.update([3, 4, 5]) # multiple addition
          print(example_set)

          example_set.remove(3) # removal
          print(example_set)

        \end{pyconsole}
        \pcon{Set element addition through \textcode{.add()} / \textcode{.update()} and removal through \textcode{.remove()}}{code:set_add_remove}

        \item \textbf{Set Operations}: Performs mathematical set operations including union, intersection, and difference.

        \begin{pyconsole}

          set_a = {1, 2, 3}
          set_b = {3, 4, 5}
          print(set_a.union(set_b))
          print(set_a.intersection(set_b))

        \end{pyconsole}
        \pcon{Set operations; \textcode{.union()} and \textcode{.intersection()}}{code:set_ops}

        \item \textbf{Frozenset}: \textcode{frozenset()} creates an \textbf{immutable} version of a set that cannot be modified after creation.

        \begin{pyconsole}

          fset = frozenset({1,2,3})
          print(type(fset))

        \end{pyconsole}
        \pcon{Frozenset using \textcode{frozenset()}}{code:frozenset}

      \end{enumerate}

    \end{core}

    \begin{core}{Dictionaries}

      A \textcode{dict} is an unordered collection of \textbf{key-value pairs} that enable efficient data lookup by key. Defined using curly braces with colon-separated pairs, dictionaries map unique keys to associated values. For example, \textcode{\{"name": "Alice", "age": 30\}} constitutes a dictionary literal.

      \begin{enumerate}

        \item \textbf{Accessing Values}: Retrieves the value associated with a specified key using bracket notation.

        \begin{pyconsole}

          example_dict = {"name": "Alice", "age": 30}
          print(example_dict["name"])

        \end{pyconsole}
        \pcon{Accessing dictionary values}{code:d_access}

        \item \textbf{Adding and Modifying}: Assigns new key-value pairs or updates existing values.

        \begin{pyconsole}

          example_dict = {"name": "Alice"}
          example_dict["age"] = 30
          print(example_dict)

        \end{pyconsole}
        \pcon{Dictionary item addition and modification}{code:d_add_mod}

        \item \textbf{Retrieving Dictionary Elements}: \textcode{.keys()}, \textcode{.values()}, and \textcode{.items()} returns a view object containing all dictionary keys, values, and key-value pairs, respectively.

        \begin{pyconsole}

          example_dict = {"name": "Alice", "age": 30}
          print(example_dict.keys(), example_dict.values())
          print(example_dict.items())

        \end{pyconsole}
        \pcon{Dictionary element retrieval using \textcode{.keys()}, \textcode{.values()}, and \textcode{.items()}}{code:d_retrieve}

      \end{enumerate}

    \end{core}

    \begin{core}{Ranges}

      A \textcode{range} is an memory-efficient immutable sequence of integers commonly used for loop iteration. It is generated using the \textcode{range()} function with \textcode{start}, \textcode{stop}, and optional \textcode{step} parameters.

      The \textbf{basic range} creates a sequence of integers from 0 up to (\textit{but not including}) a specified endpoint.

      \begin{pyconsole}

        print(list(range(5)))

      \end{pyconsole}
      \pcon{Basic range creation}{code:range_basic}

      However, you can also begin the range from a specified \textcode{start} value. Additionally, the \textcode{step} parameter allows for a specified increment between consecutive values.

      \begin{pyconsole}

        example_range = range(0, 10, 2)
        print(list(range(0, 10, 2)))

      \end{pyconsole}
      \pcon{Range with \textcode{start} and \textcode{step}}{code:range_step}

    \end{core}

    \begin{core}[label=core:bytes]{Bytes \& Bytearrays}

      \textcode{bytes} and \textcode{bytearray} objects are sequences of integer values representing raw binary data. \textcode{bytes} objects are immutable, while \textcode{bytearrays} support modification. These types are essential for binary file operations, network protocols, and low-level data manipulation.

      \begin{enumerate}

        \item \textbf{Bytes}: \textcode{b""} creates an immutable sequence of bytes from a string using specified encoding.

        \begin{pyconsole}

          example_bytes = b"hello"
          print(example_bytes, type(example_bytes))

        \end{pyconsole}
        \pcon{Bytes using \textcode{b""} syntax}{code:bytes}

        \item \textbf{Bytearray}: \textcode{bytearray()} creates a mutable sequence of bytes that can be modified after creation.

        \begin{pyconsole}

          example_bytearray = bytearray(b"hello")
          example_bytearray[0] = 72 # the byte value for "H" is 72 in ASCII/UTF-8
          print(example_bytearray)

        \end{pyconsole}
        \pcon{Bytearray creation through \textcode{bytearray()}}{code:bytearray}

        \item \textbf{Encoding and Decoding}: Converts between strings and bytes using character encodings.

        \begin{pyconsole}

          text = "hello"
          encoded = text.encode('utf-8')
          print(encoded)
          print(encoded.decode('utf-8'))

        \end{pyconsole}
        \pcon{Encoding and decoding strings to bytes through \textcode{.encode()} and \textcode{.decode()}}{code:encode_decode}

      \end{enumerate}

    \end{core}

  \subsection{Operators \& Operands}

    \begin{core}[label=core:arithmetic_operators]{Arithmetic Operators}

      \textbf{Arithmetic operators} perform mathematical calculations on numeric operands, returning numeric results.

      \begin{enumerate}

        \item \textbf{Basic Arithmetic}: \textcode{+}, \textcode{-}, \textcode{*}, \textcode{/} perform addition, subtraction, multiplication, and division on numeric operands, respectively. Division always returns a floating-point result. Note that \textcode{+} and \textcode{*} also operate on strings for concatenation and repetition (\textit{\autoref{core:string}}).

        \begin{pyconsole}

          x,y = 10, 3
          print(x + y, x - y)
          print(x * y, x / y)

        \end{pyconsole}
        \pcon{Basic arithmetic operators}{code:arithmetic_basic}
        
        \item \textbf{Modulus}: \textcode{\%} returns the remainder after division of the first operand by the second.

        \begin{pyconsole}

          x,y = 17, 5
          print(x % y)
        \end{pyconsole}
        \pcon{Modulus operator}{code:modulus}
        
        \item \textbf{Power}: \textcode{**} raises the first operand to the power of the second operand.

        \begin{pyconsole}

          x,y = 2, 3
          print(x ** y)

        \end{pyconsole}
        \pcon{Power operator}{code:power}
        
        \item \textbf{Floor Division}: \textcode{//} divides the first operand by the second and rounds down to the nearest integer.

        \begin{pyconsole}

          x,y = 17, 5
          print(x // y)

        \end{pyconsole}
        \pcon{Floor division operator}{code:floor_div}

      \end{enumerate}

    \end{core}

    \begin{core}{Assignment Operators}

      \textbf{Assignment operators} assign values to variables and can combine assignment with arithmetic operations for concise code.

      \begin{enumerate}

        \item \textbf{Basic Assignment}: \textcode{=} assigns the value on the right to the variable on the left.

        \begin{pyconsole}

          x = 10

        \end{pyconsole}
        \pcon{Basic assignment operator}{code:assign_basic}

        \textit{By convention, identifiers intended to be treated as \textbf{constants}---such as API keys or authentication credentials---are written in full capitals within the Python community, serving as an explicit signal to other developers that the value is not to be mutated at any point during program execution.}
                
        \item \textbf{Compound Assignment Operators}: \textcode{+=}, \textcode{-=}, \textcode{*=}, \textcode{/=}, \textcode{\%=}, \textcode{//=}, and \textcode{**=} combine each arithmetic operator (\textit{\autoref{core:arithmetic_operators}}) with assignment, performing the operation on the left operand with the right operand and assigning the result back to the left operand.

        \begin{pyconsole}

          x = 10
          x += 3 # addition
          print(x)
          x -= 2 # subtraction
          print(x)
          x *= 2 # multiplication
          print(x)
          x /= 4 # division
          print(x)
          # the same logic follow for modulus, floor division, and power

        \end{pyconsole}
        \pcon{Compound assignment operators}{code:assign_compound}

      \end{enumerate}

    \end{core}

    \begin{core}[label=core:comparison_operators]{Comparison Operators}

      \textbf{Comparison operators} compare two operands and return a Boolean value (\textit{\autoref{core:boolean}}) indicating the result of the comparison.

      \begin{enumerate}

      \item \textbf{Equal To}: \textcode{==} returns \textcode{True} if both operands are equal in value.

        \begin{pyconsole}

          x,y = 5, 5
          print(x == y)
          print(x == 3)

        \end{pyconsole}
        \pcon{Equality comparison operator}{code:equal}
        
        \item \textbf{Not Equal To}: \textcode{!=} returns \textcode{True} if operands are not equal in value.

        \begin{pyconsole}

          x,y = 5,3
          print(x != y)
          print(x != 5)

        \end{pyconsole}
        \pcon{Inequality comparison operator}{code:not_equal}
        
        \item \textbf{Relational Comparisons}: \textcode{<}, \textcode{>}, \textcode{<=}, and \textcode{>=} compare the magnitude of two operands, returning \textcode{True} if the left operand is less than, greater than, less than or equal to, or greater than or equal to the right operand, respectively.

        \begin{pyconsole}

          x,y = 5,3
          print(x < y)
          print(x > y)
          print(x <= 5)
          print(x >= 5)

        \end{pyconsole}
        \pcon{Relational comparison operators}{code:relational}

      \end{enumerate}

    \end{core}

    \begin{core}{Logical Operators}

      \textbf{Logical operators} combine or modify Boolean expressions, returning Boolean values based on logical relationships.

      \begin{enumerate}

        \item \textbf{And}: \textcode{and} returns \textcode{True} only if both operands are \textcode{True}.

        \begin{pyconsole}

          x,y = True, False
          print(x and x)
          print(x and y)

        \end{pyconsole}
        \pcon{\textcode{add} logical operator}{code:logical_and}
        
        \item \textbf{Or}: \textcode{or} returns \textcode{True} if at least one operand is \textcode{True}.

        \begin{pyconsole}

          x,y = True, False
          print(x or y)
          print(y or y)

        \end{pyconsole}
        \pcon{\textcode{or} logical operator}{code:logical_or}
        
        \item \textbf{Not}: \textcode{not} returns the opposite Boolean value of the operand.

        \begin{pyconsole}

          x,y = True, False
          print(not x, not y)

        \end{pyconsole}
        \pcon{\textcode{not} logical operator}{code:logical_not}

      \end{enumerate}

    \end{core}

\section{Control Flow}

  \subsection{Conditionals}

    \begin{core}{if, elif, else}

      \textbf{Conditional statements} enable selective code execution based on Boolean conditions. An \textcode{if} statement evaluates a specified condition and executes its code block only when the condition evaluates to \textcode{True}. The \textcode{elif} (\textit{else-if}) clause allows sequential evaluation of multiple conditions, executing only when all preceding conditions evaluate to \textcode{False}. The \textcode{else} clause provides a default code block that executes when all preceding conditions fail.

      \begin{pyconsole}

        x, y = 10, 5
        if x > y:
            print("x is greater than y") # conditional ends here
        elif y > x:
            print("y is greater than x")
        else:
            print("x is equal to y")

      \end{pyconsole}
      \pcon{Conditional \textcode{if} / \textcode{elif} / \textcode{else} statement block}{code:cond_statements}

    \end{core}

  \subsection{Loops}

    \begin{core}[label=core:for]{for, break, continue}

      The \textcode{for} loop enables iteration over elements in an iterable sequence (\textit{lists, tuples, strings, ranges}). Each iteration assigns the current element to a loop variable and executes the indented code block. The loop terminates automatically upon processing all elements, or manually via the \textcode{break} statement, which immediately exits the loop regardless of whether all elements have been processed.

      \begin{pyconsole}

        for num in [1, 2, 3, 4]:
            if num == 3:
                break
            print(num)

      \end{pyconsole}
      \pcon{\textcode{for} loop with \textcode{break}}{code:for_break}

      Conversely, the \textcode{continue} statement skips the remainder of the current iteration and proceeds immediately to the next iteration without terminating the loop entirely.

      \begin{pyconsole}

        for num in [1, 2, 3]:
            if num == 2:
                continue
            print(num)

      \end{pyconsole}
      \pcon{\textcode{for} loop with \textcode{continue}}{code:for_continue}

    \end{core}

    \begin{core}{while}

      The \textcode{while} loop repeatedly executes its code block as long as a specified Boolean condition remains \textcode{True}. Unlike \textcode{for} loops that iterate over finite sequences, \textcode{while} loops continue indefinitely until their condition evaluates to \textcode{False}, making them suitable for scenarios where the iteration count is not predetermined.

      \begin{pyconsole}

        x = 0
        while x < 3:
            print(x)
            x += 1

      \end{pyconsole}
      \pcon{Basic \textcode{while} loop}{code:while_basic}
      
      The \textcode{break} and \textcode{continue} statements (\textit{\autoref{core:for}}) function identically within \textcode{while} loops, allowing for premature loop termination or iteration skipping, respectively.

      \begin{pyconsole}

        x = 0
        while x < 5:
            x += 1
            if x == 2:
                continue
            if x == 4:
                break
            print(x)

      \end{pyconsole}
      \pcon{\textcode{while} loop with \textcode{continue} and \textcode{break}}{code:while_flow}

    \end{core}

\section{Functions}

  \begin{core}[label=core:def]{def}

    The \textcode{def} keyword defines a \textbf{function}---a reusable block of code that executes when called. Functions accept input through \textbf{parameters} (\textit{variables defined in the function}), process data according to their internal logic, and optionally return output values using the \textcode{return} statement.

    \begin{pyconsole}

      def greet(name):
          return f"Hello, {name}!"
      
      print(greet("Alice"))
      print(greet("Bob"))

    \end{pyconsole}
    \pcon{Basic function definition through \textcode{def}}{code:func_basic}
    
    Python supports \textbf{positional parameters} (\textit{matched by position}) and \textbf{keyword parameters} (\textit{matched by name}). Additionally, default parameter values allow functions to be called with fewer arguments than defined parameters, providing fallback values when arguments are omitted.

    \begin{pyconsole}

      def add(x, y):
          return x + y
      
      print(add(3, 5))
      print(add(x=10, y=20))
      
      def greet(name, greeting="Hello"):
          return f"{greeting}, {name}!"
      
      print(greet("Alice"))
      print(greet("Bob", "Hi"))

    \end{pyconsole}
    \pcon{\textcode{def} function positional and keyword arguments}{code:func_args}
    
    \textcode{*args} and \textcode{**kwargs} enable functions to accept variable numbers of arguments. \textcode{*args} collects excess positional arguments into a tuple, while \textcode{**kwargs} collects excess keyword arguments into a dictionary.

    \begin{pyconsole}

      def print_args(*args):
          for arg in args:
              print(arg)
      
      print_args(1, 2, 3, 4, 5)

      def print_kwargs(**kwargs):
          for key, value in kwargs.items():
              print(f"{key}: {value}")
      
      print_kwargs(name="Alice", age=30, city="NYC")

    \end{pyconsole}
    \pcon{\textcode{*args}; \textcode{def} function variable position arguments}{code:func_vargs}
    
    Functions can utilize both \textcode{*args} and \textcode{**kwargs} simultaneously to achieve maximum flexibility in parameter handling.

    \begin{pyconsole}

      def flexible_func(x, y, *args, **kwargs):
          print(f"x: {x}, y: {y}")
          print(f"args: {args}")
          print(f"kwargs: {kwargs}")
      
      flexible_func(1, 2, 3, 4, 5, name="Alice", age=30)

    \end{pyconsole}
    \pcon{\textcode{**kwargs}; \textcode{def} function variable keyword arguments}{code:func_vkwargs}

  \end{core}

  \begin{core}{lambda}

    The \textcode{lambda} keyword creates \textbf{anonymous functions}---small, unnamed functions defined in a single expression. Lambda functions are syntactically restricted to a single expression and implicitly return the result of that expression, making them suitable for simple operations that don't warrant full function definitions (\textit{\autoref{core:def}}).

    \begin{pyconsole}

      def add(x, y): # regular function
          return x + y
      
      add_lambda = lambda x, y: x + y # equivalent lambda function
      print(add(3, 5))
      print(add_lambda(3, 5))

    \end{pyconsole}
    \pcon{\textcode{lambda} function}{code:lambda_basic}
    
    Lambda functions are commonly used as \textbf{arguments to higher-order functions} that accept functions as parameters, such as \textcode{map()}, \textcode{filter()}, and \textcode{sorted()}.

    \begin{pyconsole}

      numbers = [1, 2, 3, 4, 5]
      
      squared = list(map(lambda x: x**2, numbers)) # map: apply function to each element
      print(squared)
      
      evens = list(filter(lambda x: x % 2 == 0, numbers)) # filter: keep elements where function returns True
      print(evens)
      
      words = ["apple", "pie", "zoo", "a"] # sorted: custom sorting key
      sorted_by_length = sorted(words, key=lambda x: len(x))
      print(sorted_by_length)

    \end{pyconsole}
    \pcon{\textcode{lambda} with \textcode{map()} function}{code:lambda_map}
    
    Lambda functions can \textbf{reference variables from their enclosing scope}, meaning that they have the ability to access and utilize variables that were defined outside of its own internal parameter list and thus creating closures that capture external states.

    \begin{pyconsole}

      def make_multiplier(n):
          return lambda x: x * n
      
      times_two = make_multiplier(2)
      print(times_two(5))

    \end{pyconsole}
    \pcon{\textcode{lambda} function referencing variables from their enclosing scope}{code:lambda_closure}

  \end{core}

  \begin{core}{Decorators}

    \textbf{Decorators} are functions that \textbf{modify} or enhance the behavior of other functions without altering their source code. Decorators wrap the target function, adding functionality before or after its execution, and are applied using the \textcode{@} syntax.

    \begin{pyconsole}

      def uppercase_decorator(func):
          def wrapper(*args, **kwargs):
              result = func(*args, **kwargs)
              return result.upper()
          return wrapper
      
      @uppercase_decorator
      def greet(name):
          return f"hello, {name}"
      
      print(greet("alice"))

    \end{pyconsole}
    \pcon{Basic uppercase decorator}{code:decorator_basic}
    
    Decorators can accept arguments by adding an additional layer of function nesting, enabling parameterized decoration behavior.

    \begin{pyconsole}

      def repeat(times):
          def decorator(func):
              def wrapper(*args, **kwargs):
                  for _ in range(times):
                      result = func(*args, **kwargs)
                  return result
              return wrapper
          return decorator
      
      @repeat(times=2)
      def say_hello():
          print("Hello!")
      
      say_hello()

    \end{pyconsole}
    \pcon{Parameterized multiplier decorator}{code:decorator_param}
    
    Multiple decorators can be stacked on a single function, applying transformations in bottom-to-top order (\textit{the decorator closest to the function executes first}).

    \begin{pyconsole}

      def bold(func):
          def wrapper(*args, **kwargs):
              return f"**{func(*args, **kwargs)}**"
          return wrapper
      
      def italic(func):
          def wrapper(*args, **kwargs):
              return f"_{func(*args, **kwargs)}_"
          return wrapper
      
      @bold
      @italic
      def text():
          return "Hello"
      
      print(text())

    \end{pyconsole}
    \pcon{Stacked decorators}{code:decorator_stacked}

  \end{core}

  \begin{core}{Generators}

    \textbf{Generators} are functions that use the \textcode{yield} keyword to produce a sequence of values lazily, generating each value \textbf{on-demand} rather than computing and storing all values in memory simultaneously. This enables efficient iteration over large or infinite sequences. Unlike regular functions that return once and terminate, generators \textbf{maintain their state} between \textcode{yield} statements, resuming execution from where they left off when the next value is requested.

    \begin{pyconsole}

      def count_up_to(n):
          count = 1
          while count <= n:
              yield count
              count += 1
     
      count_gen = count_up_to(10)

      for _ in range(2):
          print(next(count_gen))

      for _ in range(3): # starts from where it left off in the previous for loop
          print(next(count_gen))

    \end{pyconsole}
    \pcon{Generator state maintenance using \textcode{next()}}{code:generator_func}
    
    \textbf{Generator expressions} provide a concise syntax for creating generators, analogous to list comprehensions but with parentheses instead of brackets, \textbf{producing values lazily without constructing the entire sequence in memory}. Once a generator yields a value, that value is immediately forgotten by the generator. Once you have looped through the entire generator, it is completely empty. In programming, this is known as \textbf{generator exhaustion}.

    \begin{pyconsole}

      squares_gen = (x**2 for x in range(3))

      print(list(squares_gen))  # first time: we consume the generator

      print(list(squares_gen))  # second time: the generator is already exhausted

    \end{pyconsole}
    \pcon{Generator exhaustion}{code:generator_expr}

  \end{core}

\section{Standard Library}

  \begin{core}{Modules}

    A \textbf{module} is a single Python source file---a \textcode{.py} file---that encapsulates a logically related collection of definitions, including functions, classes, and variables, which may be imported and reused across other Python programs via the \textcode{import} statement.

    To illustrate, consider a file named \textcode{math\_utils.py} containing the following definitions.

    \begin{pyconsole}

      # math_utils.py
      def add(a, b):
          return a + b
      def subtract(a, b):
          return a - b

    \end{pyconsole}
    \pcon{\textcode{math\_utils.py} contents}{code:math_utils}

    A separate file---\textcode{main.py}, for instance---residing in the same directory may then access the definitions within \textcode{math\_utils.py} via the \textcode{import} statement. There are two conventional forms through which this may be achieved.

    \begin{enumerate}

      \item \textcode{import math\_utils} grants access to \textbf{all} definitions within \textcode{math\_utils.py}; however, each object must be qualified with the \textcode{math\_utils.} prefix upon invocation.

      \begin{pyconsole}

        # main.py
        import math_utils
        print(math_utils.add(3,2))

      \end{pyconsole}
      \pcon{\textcode{import \_} syntax module importing}{code:import1}

      To import only specific definitions rather than the module in its entirety, the \textcode{import \_.\_} syntax may be used in place of the bare \textcode{import \_} form.

      \item \textcode{from math\_utils import *} similarly exposes \textbf{all} definitions from \textcode{math\_utils.py}, but imports them directly into the calling file's namespace, eliminating the need for a qualifying prefix on each invocation.

      \begin{pyconsole}

        # main.py
        from math_utils import *
        print(add(3,2))

      \end{pyconsole}
      \pcon{\textcode{from \_ import \_} syntax module importing}{code:import2}

      This form also supports selective importing, wherein only specific definitions are brought into the calling namespace by replacing the wildcard \textcode{*} with the desired object or function.

    \end{enumerate}

    In summary, the \textcode{import \_} form imports a module by filename---excluding the \textcode{.py} extension---making its contents accessible through dot-qualified notation, whereas the \textcode{from \_ import \_} form brings definitions directly into the calling namespace, foregoing the need for prefix qualification. The latter, however, \textbf{carries the risk of namespace collisions} when multiple modules define identically named objects, and is therefore considered \textbf{poor practice} in larger projects and codebases.

  \end{core}

  \begin{core}{Packages}

    A \textbf{package} is a structured directory of \textbf{one or more related modules}, unified under a common namespace (\textit{the package name}), allowing developers to organise modules \textbf{hierarchically}, making large codebases navigable and preventing namespace collisions between identically named modules residing in different directories. An extremely basic package directory structure looks like the following.

    \dirtree{%
      .1 my\_package/.
      .2 \_\_init\_\_.py.
      .2 math\_utils.py.
      .2 string\_utils.py.
    }

    Modules within a package are accessed using dot-separated \textbf{path} notation that mirrors the directory hierarchy, with the package name serving as the top-level namespace. This structure ensures that \textcode{math\_utils} within \textcode{my\_package} remains unambiguously distinct from any identically named module elsewhere in the project, such as \textcode{string\_utils}.

  \end{core}

  \begin{core}[label=core:libraries]{Libraries}

    A \textbf{library} is a broadly distributed, reusable collection of packages and modules that provides generalised functionality intended to be shared across many independent projects. Unlike a module or package, a library is not a formally defined construct within the Python language specification itself; rather, it is an organisational and distributional concept, typically published via the \textbf{Python Package Index (PyPI)} and installable through the \textcode{pip} or \textcode{conda} package manager. The distinction between a package and a library is primarily one of scale and intent: a package is a structural unit of code organisation within a project, whereas a library is a self-contained distribution of functionality designed for broad external consumption.

    \begin{pyconsole}
      # installing a third-party library via pip (run in terminal)
      # pip install numpy
      import numpy as np               # importing the library under an alias
      arr = np.array([1, 2, 3, 4])
      print(arr * 2)                   # using functionality provided by the library
    \end{pyconsole}
    \pcon{Installing and importing a third-party library}{code:library}

    As illustrated in \autoref{code:library}, once a library has been installed into the active Python environment, its constituent packages and modules are imported using the same \textcode{import} statement as any local module, with an optional alias assigned via the \textcode{as} keyword for brevity. This uniformity of the import interface across modules, packages, and libraries is a deliberate design property of the Python language.

  \end{core}

\section{Object Oriented Programming}

  \subsection{Classes}

    \begin{core}{Classes, Attributes, and Methods}

      A \textcode{class} is a blueprint for creating objects that encapsulates data and behavior into a cohesive construct, enabling modular code organization and reusability.

      \begin{pyconsole}

        class BankAccount:
            bank = "Chase" # class attribute
            def __init__(self, owner, balance=0):
                self.owner = owner # instance attribute
                self.balance = balance # instance attribute
            def deposit(self, amount): #method
                self.balance += amount
                return self.balance
            def withdraw(self, amount):
                if amount <= self.balance:
                    self.balance -= amount
                    return self.balance
                return "Insufficient funds"
        
        account = BankAccount("Alice", 100)
        print(account.deposit(50))
        print(account.withdraw(30))
        print(account.balance)

      \end{pyconsole}
      \pcon{\textcode{class} instantiation, attributes, and methods}{code:class_basic}
      
      The \textcode{\_\_init\_\_()} method serves as a special constructor that initializes new class instances, executing automatically upon object instantiation. The \textcode{self} parameter references the specific instance being created or manipulated, providing access to that instance's attributes and methods.
      
      \textbf{Attributes} represent the data stored within a class and are categorized into two distinct types.

      \begin{itemize}

        \item \textbf{Class attributes} are shared uniformly across all instances of a class. In the \textcode{BankAccount} example, \textcode{bank = "Chase"} constitutes a class attribute accessible to all \textcode{BankAccount} objects.

        \item \textbf{Instance attributes} are unique to each individual object. Attributes such as \textcode{self.owner} and \textcode{self.balance} must be explicitly provided during instantiation, as demonstrated by \textcode{account = BankAccount("Alice", 100)}.

      \end{itemize}

      \textbf{Methods} are functions defined within a class namespace that operate on instance data. These functions are bound to the class and accessible only through class instances. In the example above, \textcode{deposit()} and \textcode{withdraw()} exemplify methods that represent the behavioral logic of the \textcode{BankAccount} class, specifically the \textcode{self.balance} attribute.

    \end{core}

    \begin{core}{Setters \& Getters}

      \textbf{Setters} and \textbf{getters} are methods that control access to an object's attributes outside of the initialization of the class. These methods of control can be written in one of two ways.

      \begin{enumerate}

        \item \textbf{Explicit Method}: The setter and getter are just written as plain functions.

        \begin{pyconsole}

          class Example:
              def setName(self, n): # setter
                  self.name = n
              def getName(self): # getter
                  return self.name

          p1 = Example()
          p1.setName("John")
          print(p1.getName())

        \end{pyconsole}
        \pcon{Explicit setter and getter method}{code:class_attrs}

        \item \textbf{Decorator Method}: The setter and getter methods are decorated with the \textcode{@property} and \textcode{@<attribute>.setter} annotations.

        By convention, attributes prefixed with a single underscore in the format of \textcode{\_attribute} indicate internal implementation details that should not be accessed directly, though Python does not enforce true privacy.

        \begin{pyconsole}

          class PythonicExample:
              def __init__(self, name):
                  self._name = name  # Protected backing attribute
              @property
              def name(self):  # Getter decorator
                  return self._name
              @name.setter
              def name(self, n):  # Setter decorator
                  if not n:
                      raise ValueError("Name cannot be empty")
                  self._name = n

          p2 = PythonicExample("John")
          p2.name = "Sally"  # Intercepted by the setter seamlessly
          print(p2.name)     # Intercepted by the getter seamlessly

        \end{pyconsole}
        \pcon{Decorator setter and getter method}{code:class_inherit}

      \end{enumerate}

      The difference is how Python handles attribute access under the hood. The explicit method relies on traditional function calls like \textcode{p1.setName()}, which creates a nightmare when trying to convert all \textcode{p1.name = <name>} lines for all class instances to the \textcode{p1.setName()} method, resulting in every file interacting with that variable having to be refactored.

      Conversely, the decorator method hooks directly into Python's descriptor protocol such as \textcode{p2.name = "Sally"} (\textit{setter}) and \textcode{p2.name} (\textit{getter}) in the above example. This wraps the underlying functions into a property descriptor object, allowing outside code to maintain the clean, direct assignment syntax of \textcode{p2.name = "Sally"}. 

      \textit{\textbf{The decorator method is simply the undisputed industry standard} way to handle setters and getters because it gives the developer the power to add data validation, transformation, or read-only access control in the background with ease. For instance, omitting the matching setter to a property getter creates a strict read-only functionality for an attribute.}

      \begin{pyconsole}

        class ReadOnlyExample:
            def __init__(self, name):
                self._name = name  # Protected backing attribute
            @property
            def name(self):  # Getter decorator
                return self._name
            # Note: The .setter decorator is intentionally omitted to make it read-only

        p3 = ReadOnlyExample("John")
        print(p3.name)     # Read access works perfectly via the getter

        # Attempting to modify the attribute will now throw an AttributeError
        p3.name = "Sally"

      \end{pyconsole}
      \pcon{Setter omission creating a read-only functionality for an attribute}{code:class_super}

    \end{core}

  \subsection{The Four Pillars of Object Oriented Programming}

    \begin{core}[label=core:encapsulation]{Encapsulation}

      \textbf{Encapsulation} is the practice of bundling data attributes and their associated methods into a cohesive class unit while restricting direct external access through access control mechanisms. This design principle protects internal state integrity by exposing controlled interfaces rather than allowing direct manipulation of object internals.
      
      \begin{pyconsole}

        class BankAccount:
            def __init__(self, owner, initial_deposit):
                self.owner = owner
                self.__balance = initial_deposit
            @property
            def balance(self):
                return f"{self.__balance:,.2f}"
            def display_balance(self):
                return f"{self.__balance:,.2f}"

        account = BankAccount("Ingyu", 1000)
        print(account.balance) # getter method
        print(account.display_balance()) # explicit function
        print(account._BankAccount__balance) # name mangling

        print(account.__balance) # private attributes cannot be directly accessed

      \end{pyconsole}
      \pcon{Encapsulation and \textcode{class} private attributes using \textcode{\_\_attribute} syntax}{code:class_prop}
      
      The double underscore prefix (\textcode{\_\_attribute}) designates an attribute as private, triggering Python's name mangling mechanism that converts the attribute name to \textcode{\_ClassName\_\_attribute}. While this prevents direct external access via the original attribute name, the value remains retrievable through properly designed accessor methods (\textit{getters}), explicit retrieval functions, or by explicitly invoking the mangled name syntax---though the latter circumvents the intended encapsulation and is considered poor practice.

    \end{core}

    \begin{core}[label=core:inheritance]{Inheritance}

      \textbf{Inheritance} is a fundamental object-oriented mechanism whereby a child class (\textit{subclass}) acquires the attributes and methods of a parent class (\textit{superclass}), facilitating code reuse and enabling the hierarchical extension of functionality without redundancy.
      
      \begin{pyconsole}

        class Animal:
            def __init__(self, name):
                self.name = name
            def eat(self):
                return f"{self.name} is eating."
            def speak(self):
                return f"{self.name} makes a generic sound."

        class Dog(Animal):
            def speak(self):
                return f"{self.name} barks: Woof!"

        my_dog = Dog("Buddy")
        print(my_dog.eat())
        print(my_dog.speak())

      \end{pyconsole}
      \pcon{Inheritance of parent \textcode{Animal} by child \textcode{Dog}}{code:class_priv}
      
      In the above code block, the \textcode{Dog} class inherits all attributes and methods from the \textcode{Animal} parent class. When a child class defines a method with an identical name to a parent class method---such as \textcode{speak()} in this example---the child implementation completely overrides the parent version, a behavior known as \textbf{method overriding}.
      
      In addition to the simple inheritance shown above, the \textcode{super()} function allows the user to return a proxy object that delegates method calls to the parent class, enabling controlled inheritance and method extension. This mechanism serves two primary purposes.
      
      \begin{itemize}

        \item \textbf{Constructor Extension}: Child class constructors frequently require both parent initialization logic and child-specific setup. The expression \textcode{super().\_\_init\_\_()} delegates baseline initialization to the parent constructor, ensuring proper attribute inheritance while permitting the addition of child-specific attributes.
        
        \item \textbf{Method Extension}: While method overriding replaces parent functionality entirely, \textcode{super().method\_name()} allows child classes to invoke parent method logic before or after executing child-specific operations, thereby extending rather than replacing inherited behavior.
        
        \begin{pyconsole}

          class Vehicle:
              def __init__(self, brand, model):
                  self.brand = brand
                  self.model = model
              def description(self):
                  return f"{self.brand} {self.model}"

          class Car(Vehicle):
              def __init__(self, brand, model, doors):
                  super().__init__(brand, model)
                  self.doors = doors
              def description(self):
                  base_info = super().description()
                  return f"{base_info} with {self.doors} doors"

          car = Car("Toyota", "Camry", 4)
          print(car.description())

        \end{pyconsole}
        \pcon{Method extension using \textcode{super()}}{code:class_readonly}

      \end{itemize}

    \end{core}

    \begin{core}[label=core:polymorphism]{Polymorphism}

      \textbf{Polymorphism} is the capacity of different classes to implement identically named methods, enabling a single unified interface to operate on diverse object types while invoking class-specific behavior. This principle allows functions to process heterogeneous objects uniformly, with runtime behavior determined by each object's concrete class implementation.

      \begin{pyconsole}

        class MasterCard:
            def process_payment(self, amount):
                return f"Processing ${amount:.2f} via MasterCard networks."

        class PayPal:
            def process_payment(self, amount):
                return f"Routing ${amount:.2f} through PayPal wallets."

        class Bitcoin:
            def process_payment(self, amount):
                return f"Broadcasting ${amount:.2f} to blockchain."

        class ApplePay:
            def process_payment(self, amount):
                return f"Authenticating ${amount:.2f} via Apple."
        
        def checkout_gate(payment_processor, total):
            print(payment_processor.process_payment(total))
        
        visa, wallet, crypto, mobile = MasterCard(), PayPal(), Bitcoin(), ApplePay()
        
        checkout_gate(visa, 150.00)
        checkout_gate(wallet, 150.00)
        checkout_gate(crypto, 150.00)
        checkout_gate(mobile, 150.00)

      \end{pyconsole}
      \pcon{Polymorphism and identically named method \textcode{process\_payment} executing different actions based on paired \textcode{class}}{code:class_methods}

      Each payment processor class implements an identically named \textcode{process\_payment()} method with class-specific logic. The \textcode{checkout\_gate()} function accepts any payment processor object and invokes its \textcode{process\_payment()} method, demonstrating polymorphic behavior: the same function call produces different outputs depending on the runtime type of the object passed as an argument. This design enables extensibility---new payment processor classes can be added without modifying the \textcode{checkout\_gate()} function, provided they implement the \textcode{process\_payment()} interface.

    \end{core}

    \begin{core}[label=core:abstraction]{Abstraction}

      \textbf{Abstraction} is a fundamental architectural principle that conceals complex, low-level implementation details behind simplified interfaces, restricting external entities to interacting only with an object's external behavior rather than its inner mechanisms, a constraint often realized through \textbf{encapsulation} (\textit{\autoref{core:encapsulation}}), \textbf{inheritance} (\textit{\autoref{core:inheritance}}), and \textbf{polymorphism} (\textit{\autoref{core:polymorphism}}).

      Explicit abstraction---facilitated by Python's \textcode{abc} library---enforces a mandatory structural baseline for all derived subclasses. Furthermore, it prohibits direct instantiation of the abstract base class, ensuring access is only mediated through its child class implementations.

      \begin{pyconsole}

        from abc import ABC, abstractmethod
        class PrinterBlueprint(ABC):
            @abstractmethod
            def print_page(self, text):
                pass

        class OfficePrinter(PrinterBlueprint): # Matches the blueprint EXACTLY
            def print_page(self, text):
                return f"Printing office document: {text}"

        class BrokenPrinter(PrinterBlueprint): # Flaw: accidental rename
            def output_text(self, text):
                return f"Printing: {text}"

        printer_1 = OfficePrinter() # success
        printer_2 = BrokenPrinter() # renamed mandatory method
        printer_3 = PrinterBlueprint() # can't call the abstract parent class

      \end{pyconsole}
      \pcon{Explicit abstraction using the \textcode{abc} module}{code:class_dunder}

      As demonstrated above, the instantiation of the \textcode{BrokenPrinter} class fails because it neglects to implement the required \textcode{print\_page()} method prescribed by its abstract base class, \textcode{PrinterBlueprint}. Conversely, the \textcode{OfficePrinter} instantiation succeeds because it strictly adheres to the same method signature outlined within \textcode{PrinterBlueprint}.

    \end{core}

\section{Error Handling \& Debugging}

  \subsection{Exceptions Handling}

    \begin{core}{Exceptions}

      \textbf{Exceptions} are runtime errors that cause the abnormal termination of a program and its resources. Examples include \textcode{ZeroDivisionError}, which occurs when attempting to divide a value by zero, and \textcode{IndexError}, which arises when accessing an element within a collection (\textit{such as a list or array}) using an invalid index.

    \end{core}

    \begin{core}{Custom Exceptions}

      Developers can define \textbf{custom exceptions} by subclassing the base \textcode{Exception} class, which can subsequently be triggered using the \textcode{raise} statement.

      \begin{pyconsole}

        class InvalidAgeError(Exception):
            pass # no need for constructor

        def verify_age(age):
            if age < 0:
                raise InvalidAgeError(f"Age cannot be negative. Received: {age}")
            print(f"Age {age} successfully verified.")

        try:
            print("System: Verifying user age...")
            verify_age(-5)
            
        except InvalidAgeError as e:
            print(f"Error Type: {type(e).__name__}")
            print(f"Error Message: {e}")

      \end{pyconsole}
      \pcon{Custom \textcode{InvalidAgeError} exception}{code:class_abc}

      As demonstrated above, the custom exception subclass does not require an explicit constructor. It inherits the constructor from the base \textcode{Exception} class, which is already designed to accept arguments---specifically, a string representing an error message.

    \end{core}

    \begin{core}{try, except, \& finally}

      The \textcode{try}, \textcode{except}, and \textcode{finally} structure provides a mechanism to manage and handle exceptions that arise during the execution of a designated block of code.

      \begin{pyconsole}

        try:
            print("Attempting the calculation...")
            result = 10 / 0
            
            print(f"The result is {result}") # This line will be skipped because the error happens above

        except ZeroDivisionError:
            print("Error: You cannot divide a number by zero!")
        finally:
            print("Cleanup: The division operation has finished.")

      \end{pyconsole}
      \pcon{Exception handling with \textcode{try} / \textcode{except} / \textcode{finally} block}{code:exc_custom}

      As demonstrated above, the code within the \textcode{try} block executes first. If a specified exception---in this case, a \textcode{ZeroDivisionError}---is raised, the runtime environment prevents premature termination and transfers control to the \textcode{except} block. The \textcode{finally} block subsequently executes regardless of whether the \textcode{try} block succeeded or failed. Consequently, the \textcode{finally} block is typically reserved for essential cleanup operations, such as terminating database connections or closing files.

      If a specific exception type is not explicitly defined, a generic \textcode{except} block will default to catching all potential exceptions. This approach is generally considered \textbf{poor practice}, as it can obscure unrelated bugs and lead to unpredictable program behavior, particularly in complex software.

      \begin{pyconsole}

        try:
            print("Attempting the calculation...")
            result = 10 / 0
            
            print(f"The result is {result}") # This line will be skipped because the error happens above

        except: # catches ALL errors
            print("Error: You cannot divide a number by zero!")
        finally:
            print("Cleanup: The division operation has finished.")

      \end{pyconsole}
      \pcon{Catching all exceptions with generic \textcode{except:} header; \textit{poor practice}}{code:exc_try}

      A more robust practice involves implementing multiple \textcode{except} headers to handle distinct exception types individually. Utilizing the base \textcode{Exception} class as a fallback, paired with \textcode{as e} to capture the error object, allows the program to safely identify and log unexpected exceptions while maintaining application stability.

      \begin{pyconsole}

        try:
            user_input = "Hello"
            number = int(user_input)

        except ValueError as e:
            print(f"The message is: {e}")
            print(f"The error name is: {type(e).__name__}")
        except Exception as e: # This is a fallback that catches anything else and prints its name
            print(f"An unexpected {type(e).__name__} occurred: {e}")

      \end{pyconsole}
      \pcon{Multiple \textcode{except} blocks}{code:exc_multi}

    \end{core}

  \subsection{Logging}

    \begin{core}{Logging}

      \textbf{Logging} is a systematic mechanism for tracking events, errors, and state changes that occur during software execution. While standard \textcode{print()} statements are frequently utilized for \textit{preliminary} debugging, the built-in \textcode{logging} library provides a more robust framework suitable for larger applications. It allows developers to \textbf{categorize outputed messages by severity}.

      The logging framework categorizes events into five primary severity levels, listed in increasing order of critical importance: \textcode{DEBUG}, \textcode{INFO}, \textcode{WARNING}, \textcode{ERROR}, and \textcode{CRITICAL}. By establishing a minimum severity threshold, the runtime environment can automatically filter out lower-level messages, ensuring that only pertinent information is captured and recorded.

      \begin{pyconsole}

        import sys
        import logging

        logging.basicConfig(level=logging.WARNING, format='%(levelname)s: %(message)s', stream=sys.stdout, force=True) # force=True and stream=sys.stdout is needed to output the logs within this pyconsole environment

        def divide_values(a, b):
            # This will be suppressed because DEBUG is lower than WARNING
            logging.debug(f"Attempting to divide {a} by {b}.") 
            if b == 0:
                # This will be captured because ERROR is higher than WARNING
                logging.error("Division by zero attempted.")
                return None
            result = a / b
            # This will be suppressed because INFO is lower than WARNING
            logging.info(f"Division successful. Result is {result}.") 
            return result

        logging.warning("System is operating with minimal resources.")
        divide_values(10, 0)

      \end{pyconsole}
      \pcon{\textcode{logging} module usage at \textcode{WARNING} level}{code:exc_finally}

      To retain log records for historical reference, a destination file can be specified using the \textcode{filename} parameter within the \textcode{logging.basicConfig()} function, which will route all subsequent log entries to that designated file.

    \end{core}

  \subsection{Assertion}

    \begin{core}{Assertions}

      An \textbf{assertion} is a programmatic debugging aid that functions as an internal sanity check. It allows developers to explicitly declare a condition that must evaluate to true at a specific point during execution. If the condition holds true, the program proceeds normally without interruption. However, if the condition evaluates to false, the runtime environment immediately halts execution and raises an \textcode{AssertionError}.

      In Python, assertions are implemented utilizing the \textcode{assert} keyword, which evaluates a boolean expression and can optionally include a diagnostic error message.

      \begin{pyconsole}

        def apply_discount(original_price, discount_rate):
            # Assert that the parameters fall within logically valid bounds
            assert original_price > 0, "The original price must be strictly positive."
            assert 0 <= discount_rate <= 1, "The discount rate must be between 0 and 1."
            return original_price * (1 - discount_rate)

        final_price = apply_discount(100.0, 0.2) # This will execute successfully
        print(f"Discounted price: {final_price}")

        apply_discount(-50.0, 0.2) # This will immediately trigger an AssertionError

      \end{pyconsole}
      \pcon{Internal logic verification through \textcode{assert} keyword}{code:logging}

      In practice, assertions are designed to \textbf{verify internal logic} and identify states that the developer considers computationally impossible, primarily used as tools for development and testing phases. 

    \end{core}

\section{File Input/Output and Data Handling}

  \begin{core}{Files}

    A \textbf{file} is a continuous, one-dimensional \textbf{stream} of data---either plain text characters or raw binary bytes---that an application can sequentially read from or write to during execution.

  \end{core}

  \begin{core}{File Input/Output}

    To interact with a file, a program must request a \textbf{file object} from the operating system. This object acts as a temporary communication bridge between the application's volatile memory and the persistent storage drive. The fundamental lifecycle of programmatic File I/O strictly adheres to three sequential phases.

    \begin{enumerate}

      \item \textbf{Open:} Establishing the stream connection and declaring the intended access mode.

      \begin{itemize}

        \item \textcode{'r'} / \textbf{read}: Opens a file exclusively for reading, positioning the stream at the beginning of the document. If the specified file does not exist, the runtime raises a \textcode{FileNotFoundError}.

        \item \textcode{'w'} / \textbf{write}: If the file already exists, its \textbf{existing contents are immediately truncated} (\textit{completely overwritten}) before new data is introduced. If it does not exist, a new file is generated.

        \item \textcode{'a'} / \textbf{append}: Opens a file for writing but \textbf{preserves existing data} by positioning the stream at the very end of the document. Any newly transmitted data is appended to the conclusion of the file. If the file does not exist, a new one is created.

        \item \textcode{'x'} / \textbf{exclusive creation}: Opens a file strictly for writing, functioning as a safeguard against data loss. \textbf{The file must not exist prior to execution}; if it does, a \textcode{FileExistsError} is raised, intentionally aborting the operation.

      \end{itemize}

      If working with binary files, simply append \textcode{'b'} to the end: \textcode{'rb'}, \textcode{'wb'}, \textcode{'ab'}, \textcode{'xb'}

      \item \textbf{Process:} Transmitting data through the stream via read or write operations.

      \item \textbf{Close:} Severing the connection to flush internal memory.

    \end{enumerate}

    Modern Python development heavily relies on the \textcode{with} statement, which acts as a context manager. This structure guarantees that the file stream is \textbf{automatically and safely closed once the nested block of code finishes execution}, even if an unexpected exception is raised during the processing phase.

    \begin{pyconsole}

      with open("sensor_data.txt", "w") as file_stream:
          _ = file_stream.write("timestamp: 001, status: active\n")
          _ = file_stream.write("timestamp: 002, status: active\n")
          # file stream is automatically closed upon exiting this block

      with open("sensor_data.txt", "r") as file_stream:
          content = file_stream.read()
          print(content)

    \end{pyconsole}
    \pcon{File opening and closing through \textcode{with} statement}{code:file_io}

  \end{core}

  \begin{core}{Serialization and Pickling}

    In data handling, \textbf{serialization} is the process of converting an in-memory object into a byte stream suitable for storage or transfer. In Python, this implemented via the \textcode{pickle} module. The inverse operation---reconstructing a Python object from a byte stream---is known as \textbf{deserialization} (\textit{or unpickling}).

    Pickling is highly advantageous when working with complex, custom data structures that cannot be easily represented in standard, human-readable text formats like JSON or CSV.

    The \textcode{pickle} API primarily relies on two functions for file interactions:

    \begin{itemize}

        \item \textcode{pickle.dump(obj, file)} serializes the target object and writes the resulting bytes directly to an open binary file stream.

        \item \textcode{pickle.load(file)} reads a binary file stream containing a serialized byte string and reconstructs the original Python object.

    \end{itemize}

    \begin{pyconsole}

      import pickle

      session_data = { # complex data structure
          "user_id": 1042,
          "permissions": ["admin", "developer"],
          "matrix_weights": (0.85, 0.12, 0.94)
      }

      with open("session.pkl", "wb") as binary_stream: # serializing data
          pickle.dump(session_data, binary_stream)

      with open("session.pkl", "rb") as binary_stream: # deserializing data
          retrieved_data = pickle.load(binary_stream)

      print(f"Data Type: {type(retrieved_data)}")
      print(f"Content: {retrieved_data}")

    \end{pyconsole}
    \pcon{Pickle object serialization through \textcode{pickle} module commands \textcode{.dump()} and \textcode{.load()}}{code:pickle}

    \textit{It is important to keep in mind that deserializing a corrupted or maliciously constructed byte stream can trigger arbitrary code execution within the runtime environment. Consequently, objects should never be unpickled from untrusted or unauthenticated external sources.}

  \end{core}

\section{Regular Expression}

  \begin{core}[label=core:regex]{Regular Expression}

    \textbf{Regular expressions (regex)} are character sequences or structural patterns that, when evaluated by the \textcode{re} module, enable developers to perform substring searches and pattern validation against a given string.

  \end{core}

  \begin{core}[label=core:seq_char]{Sequence Characters}

    A regular expression pattern may be composed of raw literal characters, such as \textcode{a} or \textcode{b}, or \textbf{sequence characters}, which are predefined escape sequences that each represent a distinct subset of the full Unicode character space.

    \begin{itemize}

      \item \textcode{\textbackslash d} / \textbf{Digits}: Matches any numeric digit character from 0 to 9.

      \item \textcode{\textbackslash D} / \textbf{Non Digits}: Matches any character that is not a numeric digit.

      \item \textcode{\textbackslash s} / \textbf{White Space}: Matches whitespace characters such as spaces, tabs, and newline characters.

      \item \textcode{\textbackslash S} / \textbf{Non White Space}: Matches any character that is not a whitespace character.

      \item \textcode{\textbackslash w} / \textbf{Alphanumeric}: Matches alphanumeric characters and underscores.

      \item \textcode{\textbackslash W} / \textbf{Non Alphanumeric}: Matches any character that is not alphanumeric or an underscore.

      \item \textcode{\textbackslash b} / \textbf{Word Boundary}: Matches positions surrounding complete words.

      \item \textcode{\textbackslash A} / \textbf{Start of String}: Restricts the search to the beginning of the string.

      \item \textcode{\textbackslash Z} / \textbf{End of String}: Restricts the search to the end of the string.

    \end{itemize}

  \end{core}

  \begin{core}{Core Regular Expression Functions}

    The \textcode{re} module exposes several core functions that make up the primary toolset for applying regular expressions against a string. Each function differs in its scope of search and the form of its return value, as demonstrated in the following list.

    \begin{enumerate}

      \item The \textcode{re.search()} function scans the entire string and returns a \textbf{match object} corresponding to the first occurrence of the pattern, or \textcode{None} if no match is found; the exact matched substring is then retrievable via the \textcode{.group()} method on that object.

      \begin{pyconsole}

        import re
        string = "Take 1 up One 23 idea. One idea 45 at a time"

        result = re.search(r'O\w',string)
        print(result.group())

      \end{pyconsole}
      \pcon{\textcode{re.search()} paired with \textcode{.group()} returning the first matching substring}{code:re_search}

      \item The \textcode{re.findall()} function traverses the full string and returns a list of all non-overlapping matches, making it the appropriate choice when multiple occurrences are expected. This does not need to paired with the \textcode{.group} method.

      \begin{pyconsole}

        import re
        string = "Take 1 up One 23 idea. One idea 45 at a time"

        result = re.findall(r'O\w\w',string)
        print(result)

      \end{pyconsole}
      \pcon{\textcode{re.findall()} returning a list of matching substrings}{code:re_findall}

      \item The \textcode{re.match()} function---paired with the \textcode{.group()} method---is more restrictive, as it anchors its search \textbf{exclusively to the beginning of the string} and returns \textcode{None} for any pattern not satisfied at that position.

      \begin{pyconsole}

        import re
        string = "Take 1 up One 23 idea. One idea 45 at a time"

        result = re.match('T\w\w',string)
        print(result.group())

      \end{pyconsole}
      \pcon{\textcode{re.match()} paired with \textcode{.group()} returning the matching substring at the beginning of reference string}{code:re_match}

      \item The \textcode{re.sub()} performs an in-place substitution of all matched substrings with a specified replacement

      \begin{pyconsole}

        import re
        string = "Take 1 up One 23 idea. One idea 45 at a time"

        result = re.sub(r'One','Two',string)
        print(result)

      \end{pyconsole}
      \pcon{\textcode{re.sub()} replacing all matched substrings}{code:re_sub}

      \item The \textcode{re.split()} partitions the string into a list of substrings at each position where the pattern is matched.

      \begin{pyconsole}

        import re
        string = "Take 1 up One 23 idea. One idea 45 at a time"

        result = re.split(r'\d+',string)
        print(result)

      \end{pyconsole}
      \pcon{\textcode{re.split()} spliting given string at all match substring positions}{code:re_split}

    \end{enumerate}

  \end{core}

  \begin{core}[label=core:quantifier]{Quantifiers}

    \textbf{Quantifiers} extend the expressive power of a regex pattern by specifying the number of times a preceding character or sequence character must occur in order for a match to be satisfied. They may enforce an exact repetition count or define a permissible range.

    \begin{enumerate}

      \item The \textcode{\{m\}} quantifier constrains the preceding token to exactly $m$ repetitions, whereas \textcode{\{m,n\}} defines an inclusive range between a minimum of $m$ and a maximum of $n$ repetitions.

      \begin{pyconsole}

        import re
        string = "Take 1 up One 23 idea.One idea 45 at a Time"

        result = re.findall(r'O\w{1}',string) #{m} exactly m repetition
        print(result)

        result = re.findall(r'O\w{1,2}',string) #{m,n} m minimum, n maximum repetitions
        print(result)

      \end{pyconsole}
      \pcon{Regexes using quantifiers}{code:regex_quant1}

      \item The \textcode{+} quantifier requires one or more occurrences, \textcode{*} permits zero or more, and \textcode{?} allows either zero or one, effectively rendering the preceding token optional.

      \begin{pyconsole}

        import re
        string = "Take 1 up One 23 idea.One idea 45 at a Time"

        result = re.findall(r'O\w+',string) #+ one or more repetitions
        print(result)

        result = re.findall(r'O\w*',string) #* zero or more repetitions
        print(result)

        result = re.findall(r'O\w?',string) #? zero or one repetitions
        print(result)

      \end{pyconsole}
      \pcon{Regexes using quantifiers}{code:regex_quant2}

    \end{enumerate}

    Mind that quantifiers are greedy by default, meaning the engine will consume as many characters as possible while still producing an overall match. For instance, the \textcode{{1,2}} quantifier in \autoref{code:regex_quant1} yields a list of \textcode{'One'} strings rather than \textcode{'On'}, as the engine greedily consumes the maximum number of permitted repetitions.

  \end{core}

  \begin{core}{Special Characters}

    In addition to \textbf{sequence characters} (\textit{\autoref{core:seq_char}}) and \textbf{quantifiers} (\textit{\autoref{core:seq_char}}), the \textcode{re} module supports a set of \textbf{special characters} that modify the structural behaviour of a pattern, such as constraining its position within the string, escaping reserved metacharacters, or expressing logical alternation between sub-patterns.

    \begin{enumerate}

      \item The unescaped dot \textcode{.} serves as a wildcard, matching any single character except a newline; when a literal dot is intended, it must be escaped as \textcode{\textbackslash .} to suppress its metacharacter interpretation. This escaping convention applies universally to all reserved metacharacters within the \textcode{re} module.

      \begin{pyconsole}

        import re
        string = "I live .. like cats oh yeah"

        result = re.search(r'l..e',string)
        print(result.group())

        result = re.search(r'\.\.',string)

        print(result.group())

      \end{pyconsole}
      \pcon{\textcode{.} and \textcode{\textbackslash .} special characters}{code:regex_special1}

      \item The anchors \textcode{\^{}} and \textcode{\$} constrain a match to the start and end of the string respectively, analogously to \textcode{\textbackslash A} and \textcode{\textbackslash Z}. 

      \begin{pyconsole}

        import re
        string = "I live .. like cats oh yeah"

        result = re.search(r'^I...',string) # beginning
        print(result.group())

        result = re.search(r'...h$',string) # end
        print(result.group())

      \end{pyconsole}
      \pcon{Regex matching at the beginning and end of given string using \textcode{\^} and \textcode{\$}}{code:regex_special2}

      \item Character classes, denoted by \textcode{[...]}, define an explicit set of permissible characters at a given position, while the negated form \textcode{[\^{}...]} inverts this constraint to match any character outside the specified set.

      \begin{pyconsole}

        import re
        string = "I live .. like cats oh yeah"

        result = re.search(r'[aeiou]',string)
        print(result.group())

        result = re.search(r'[^I li]',string)
        print(result.group())

      \end{pyconsole}
      \pcon{Defining sets of permissible characters in a regex}{code:regex_special3}

      \item The alternation operator \textcode{(R|S)} evaluates two or more sub-expressions and returns a match if either is satisfied, providing a concise mechanism for expressing logical disjunction within a pattern.

      \begin{pyconsole}

        import re
        string = "I live .. like cats oh yeah"

        result = re.search(r'(cats|dogs)',string) #(R|S) specifies multiple regular expressions to match; either R OR S
        print(result.group())

      \end{pyconsole}
      \pcon{Alternation operator \textcode{(R|S)} in regex matching}{code:regex_special4}

    \end{enumerate}

  \end{core}

\section{Threading}

  \begin{core}{Threading \& Global Interpreter Lock (GIL)}

    So far, all previous coding examples shown have been \textbf{single-threaded}, meaning that line 1 finishes before moving onto line 2, line 3, and so on. However, with the \textcode{threading} module, a developer is able to execute several concurrent operations within a single \textbf{multi-threaded} process in a practice called \textbf{threading}.

    While, in theory, threading allows for simultaneous execution of code, threading specifically in Python works slightly differently due to a mechanism called the \textbf{Global Interpreter Lock (GIL)}. The GIL is a safety mechanism built into CPython (\textit{\autoref{core:cpython}}) that acts as a master lock on Python's memory and thus prevents multiple threads from executing Python bytecodes exactly simultaneously. As a consequence, the \textcode{threading} module does not necessarily allow different code executions to progress in true parallel, but rather rapidly passes the single GIL back and forth between threads, often yielding the lock during a thread's \textbf{downtime} (\textit{periods of waiting for external operations, such as network requests, file I/O, or user input}).

  \end{core}

  \begin{core}{Main Thread}

    The main thread that is always running is called the \textcode{MainThread}, which can be retrieved through the \textcode{threading} module.

    \begin{pyconsole}

      import threading

      print('Current thread that is running: {}'.format(threading.current_thread().name))

      if threading.current_thread() == threading.main_thread():
          print('Main Thread')

    \end{pyconsole}
    \pcon{\textcode{MainThread} confirmation}{code:main_thread}

  \end{core}

  \subsection{Threading Methods}

    \begin{core}[label=core:threading_function]{Threading Through Functions}

      Threading in its most elementary form is invoked by passing a callable into the \textcode{Thread} object, which instantiates a new thread of execution. The \textcode{Thread} constructor accepts two principal parameters: \textcode{target}, which holds a reference to the function object in its non-invoked state, and \textcode{args}, which supplies the positional arguments to that function as a \textbf{tuple}.

        \begin{pyconsole}

          import threading

          def displayNumbers(count):
              i = 0
              print(threading.current_thread().name) 
              while i <= count:
                  print(i)
                  i += 1

          print(threading.current_thread().name)

          # notice the args value below is a tuple
          t = threading.Thread(target=displayNumbers, args = (5,), name = 'displayNumbersThread') 
          t.start()
          t.join()
          print("displayNumbers function finished")

        \end{pyconsole}
        \pcon{Simple threading via a function}{code:threading_function}

      As demonstrated above, the thread object \textcode{t} is dispatched via the \textcode{.start()} method, which schedules the thread for execution and returns immediately, allowing the main thread to continue concurrently. It is important to distinguish \textcode{.start()} from the lower-level \textcode{.run()} method: whereas \textcode{.start()} delegates execution to a newly spawned OS-level thread, \textcode{.run()} invokes the target callable directly on the \textit{calling} thread, producing strictly \textbf{sequential rather than concurrent behaviour}.

      The \textcode{.join()} method causes the main thread to halt until \textcode{t} has completed execution, thereby synchronising the two threads before control advances to subsequent statements. In this example, the main thread is suspended until \textcode{displayNumbers} returns, after which the final print statement is reached.

      Finally, observe that invoking \textcode{threading.current\_thread().name} from within \textcode{t}'s execution context yields \textcode{displayNumbersThread}, reflecting the identifier supplied via the \textcode{name} parameter at construction time. This illustrates that each \textcode{Thread} instance maintains its own execution context, including thread-local identity metadata accessible at runtime.

    \end{core}

    \begin{core}{Threading Through Class Methods}

      Analogously to the function-based approach demonstrated in \autoref{core:threading_function}, threads may equally be dispatched by targeting instance methods of a class.

      \begin{pyconsole}

        import threading
        from time import sleep # the sleep function simply makes the program wait

        class MyThread:
            def displayNumbers(self):
                i = 0
                print(threading.current_thread().name)
                while i <= 3:
                    print(i)
                    i+=1

        obj = MyThread()

        t1 = threading.Thread(target=obj.displayNumbers,name='displayNumbers1')
        t1.start()
        sleep(0.5)

        t2 = threading.Thread(target=obj.displayNumbers,name='displayNumbers2')
        t2.start()
        t1.join()
        t2.join()

      \end{pyconsole}
      \pcon{Multi-threading via a class method}{code:threading_class}

      The \textcode{sleep(0.5)} calls serve to introduce a deliberate delay between the dispatch of \textcode{t1} and \textcode{t2}, imposing an approximate execution ordering. In their absence, the relative scheduling of the two threads is delegated entirely to the Python thread scheduler, which provides no ordering guarantees---the threads may interweave arbitrarily or execute in an effectively simultaneous fashion depending on the underlying system load.

    \end{core}

    \begin{core}{Common Producer/Consumer Pattern}

      The producer-consumer pattern is one of the most canonical demonstrations of multi-threaded coordination, wherein two threads operate concurrently on a shared resource.

      \begin{pyconsole}

        import threading
        import time

        class Producer:
            def __init__(self):
                self.products = []
                self.ordersplaced = False
            def produce(self):
                for i in range(1,5):
                    self.products.append('Product'+str(i))
                    time.sleep(1)
                    print('Item Added')
                self.ordersplaced = True

        class Consumer:
            def __init__(self,prod):
                self.prod = prod
            def consume(self):
                while self.prod.ordersplaced == False:
                    print("Waiting for the orders")
                    time.sleep(0.4)
                print('Orders Shipped {}'.format(self.prod.products))

        p = Producer()
        c = Consumer(p)

        t1 = threading.Thread(target = p.produce)
        t2 = threading.Thread(target = c.consume)

        t1.start()
        t2.start()
        t1.join()
        t2.join()

      \end{pyconsole}
      \pcon{Multi-threading consumer \& producer pattern}{code:consumer_producer}

      As illustrated in \autoref{code:consumer_producer}, the consumer thread \textcode{t2} continuously polls the shared \textcode{ordersplaced} flag within a busy-wait loop, deferring execution of the shipment statement until the flag evaluates to \textcode{True}. This state transition is driven by the producer thread \textcode{t1}, which iteratively populates the product list via its \textcode{for} loop before setting \textcode{ordersplaced = True} upon completion.

    \end{core}

  \subsection{Locks}

    \begin{core}[label=core:locks]{Locks}

      When multiple threads access a shared resource concurrently, conditions may arise in which overlapping operations produce inconsistent or corrupted state. To prevent this, Python's \textcode{threading} module provides the \textcode{Lock()} class, which enforces \textbf{mutual exclusion} by ensuring that at most one thread may execute a designated critical section at any given time.

      \begin{pyconsole}

        import threading

        class BookMyBus:
            def __init__(self,availableSeats):
                self.availableSeats = availableSeats
                self.l = threading.Lock()
            def buy(self,seatsRequested):
                self.l.acquire() #starting the locked environment
                print('Total seats available: {}'.format(self.availableSeats))
                if(self.availableSeats>=seatsRequested):
                    print('Confirming a seat')
                    print('Processing the payment')
                    print('Printing the Ticket')
                    self.availableSeats-=seatsRequested
                else:
                    print('Sorry. No seats available')
                self.l.release() #ending the locked environment

        obj = BookMyBus(10)

        t1 = threading.Thread(target=obj.buy,args=(3,))
        t2 = threading.Thread(target=obj.buy,args=(4,))
        t3 = threading.Thread(target=obj.buy,args=(4,))

        t1.start()
        t2.start()
        t3.start()
        t1.join()
        t2.join()
        t3.join()

      \end{pyconsole}
      \pcon{Threading locks enforcing mutual exclusion}{code:locks}

      The critical section---the entirity of the \textcode{buy} method---is surrounded by paired calls to \textcode{.acquire()} and \textcode{.release()}. When a thread invokes \textcode{.acquire()}, it attempts to take ownership of the lock: if the lock is currently unheld, the thread acquires it and proceeds into the critical section; if another thread already holds the lock, the calling thread blocks until the lock is relinquished. Once the protected operations are complete, \textcode{.release()} surrenders ownership of the lock, allowing the next waiting thread to acquire it and enter the critical section in turn.

    \end{core}

    \begin{core}{Thread Synchronisation}

      \textbf{Thread synchronisation} (\textit{communication}) is facilitated through the \textcode{Condition} class and its associated methods, \textcode{wait()} and \textcode{notify()}; these methods must be invoked within a locked context in order to prevent data corruption.

      \begin{pyconsole}

        import threading
        import time

        class Producer:
            def __init__(self):
                self.products = []
                self.c = threading.Condition() # the Condition class already has the lock method in-built into it, thus you don't need to invoke a separate lock method
            def produce(self):
                self.c.acquire() # locked environment setting through the Condition class
                for i in range(1,5):
                    self.products.append('Product'+str(i))
                    time.sleep(1)
                    print('Item Added: Product' + str(i))
                self.c.notify() # where the program ends and notifies the consumer
                self.c.release()

        class Consumer:
            def __init__(self,prod):
                self.prod = prod
            def consume(self):
                self.prod.c.acquire()
                self.prod.c.wait() 
                self.prod.c.release()
                print('Orders Shipped: {}'.format(self.prod.products))
        p = Producer()
        c = Consumer(p)

        t1 = threading.Thread(target = p.produce)
        t2 = threading.Thread(target = c.consume)

        t1.start()
        t2.start()

        t1.join()
        t2.join()

      \end{pyconsole}
      \pcon{Threading using the \textcode{Condition} class}{code:threading_condition}

      Consider the scenario in which the Python runtime schedules the \textcode{t2} thread (\textit{consumer thread}) first; upon entering \textcode{consume()}, it acquires the lock and immediately finds the product list empty, as the producer has not yet executed. This results in a deadlock: the lock remains held within the \textcode{consume()} block, preventing the \textcode{produce()} function from acquiring it, since both threads contend over the same underlying \textcode{Condition} instance \textcode{self.c} and \textcode{self.prod.c}.

      To prevent the above deadlock scenario, the \textcode{wait()} method---as seen in \autoref{code:threading_condition}---performs three critical operations.

      \begin{enumerate}[label=(\arabic*)]

        \item It \textbf{automically releases the lock} held within the \textcode{acquire()} / \textcode{release()} block of the \textcode{consume()} function, returning it to the general pool so that the producer thread may acquire it.

        \item It suspends the calling thread and places it into an internal waiting queue managed by the \textcode{Condition} object.

        \item It remains suspended in the waiting queue until explicitly signalled by a call to \textcode{notify()}.

      \end{enumerate}

      Once the lock is released back to the pool, the scheduler grants it to the \textcode{t1} thread (\textit{producer thread}), which enters \textcode{produce()}, populates the product list, and completes its work. Prior to calling \textcode{release()}, the producer invokes \textcode{notify()}, which promotes the consumer thread \textcode{t2} from the waiting queue back to a runnable state, subsequently allowing it to acquire the lock and correctly print the shipped orders.

      In summary, the \textcode{wait()}--\textcode{notify()} mechanism is a tool designed explicitly to handle unpredictable scheduling order arising from \textbf{race conditions} (\textit{the Free-For-All race}), and to enforce a correct, deterministic execution sequence across cooperating threads.

    \end{core}
    
  \subsection{Queuing}

    \begin{core}{Queuing}

      The \textcode{queue} module provides a thread-safe mechanism for passing objects between threads, offering a simpler and more robust alternative implementation of the producer-consumer pattern with locks (\textit{\autoref{core:locks}}).

      \begin{pyconsole}

        import random
        import time
        import queue
        import threading

        def producer(q):
            for _ in range(2):
                print('Producing')
                q.put(random.randint(1,50)) #putting the random integer into a queue
                print('Produced')
                time.sleep(0.5)

        def consumer(q):
            for _ in range(2):
                print('Ready to consume')
                print('Consume Data: {}'.format(q.get())) #returning the queued integer
                time.sleep(0.5)

        q = queue.Queue()
        t1 = threading.Thread(target=consumer,args=(q,))
        t2 = threading.Thread(target=producer,args=(q,))

        t1.start()
        t2.start()
        t1.join()
        t2.join()

      \end{pyconsole}
      \pcon{Queueing using \textcode{Queue()}}{code:queue}

      As illustrated in \autoref{code:queue}, the \textcode{Queue()} class internally manages all requisite locking, ensuring that concurrent \textcode{put()} and \textcode{get()} operations across multiple threads remain free from race conditions and data corruption. Specifically, the \textcode{put()} method enqueues the random integer generated by \textcode{producer()} into the shared \textcode{q} object, while the \textcode{get()} method dequeues and returns the first item in FIFO order for consumption by \textcode{consumer()}, which outputs the retrieved value via a \textcode{print} statement.

    \end{core}

    \begin{core}{Alternative Queue Ordering}

      Beyond the default FIFO ordering, the \textcode{queue} module exposes alternative queue classes that govern the order in which elements are dequeued, providing developers with flexible retrieval strategies suited to different scheduling requirements.

      \begin{pyconsole}

        import queue

        lq = queue.LifoQueue() # last in first out
        lq.put(400)
        lq.put(100)
        lq.put(500)
        lq.put(50)
        while not lq.empty(): # this is another function to specify an empty queue
            print(lq.get(), end=' ')
        print()

        pq = queue.PriorityQueue() #in order
        pq.put(400)
        pq.put(100)
        pq.put(500)
        pq.put(50)
        while not pq.empty():
            print(pq.get(), end=' ')
        print()

        pq = queue.PriorityQueue()
        pq.put((400,'John')) # if the item in the queue is a str, then make a tuple with a int in the first index and it will use that number to define the order
        pq.put((100,'Bob'))
        pq.put((500,'Ahmed'))
        pq.put((50,'Bharath'))
        while not pq.empty():
            print(pq.get()[1], end=' ') #insert the index to choose only the name in the prioritized order

      \end{pyconsole}
      \pcon{Custom queue ordering}{code:queue_order}

      As demonstrated in \autoref{code:queue_order}, the \textcode{LifoQueue} class implements a last-in, first-out retrieval policy, whereby the most recently enqueued element is always dequeued first. The \textcode{PriorityQueue} class, by contrast, dequeues elements in ascending order of their priority value; when the enqueued items are non-numeric, a tuple of the form \textcode{(priority, item)} may be supplied, whereupon the queue uses the integer at index zero to determine the retrieval order, with only the associated item at index one being extracted for use.

    \end{core}

  \subsection{Daemon Threads}

    \begin{core}{Daemon Threads}

      A \textbf{daemon thread} is a thread that runs silently in the background and is automatically terminated by the Python runtime as soon as all non-daemon threads have completed execution. Unlike standard threads, daemon threads are not awaited by the interpreter upon program exit, meaning any work they have not yet completed is abandoned without notice when the main thread finishes.

      \begin{pyconsole}

        import threading
        import time

        def background_task():
            while True:
                print('Daemon running...')
                time.sleep(0.5)

        def main_task():
            for i in range(3):
                print('Main thread working: step {}'.format(i))
                time.sleep(1)

        t1 = threading.Thread(target=background_task)
        t1.daemon = True # designates t1 as a daemon thread
        t2 = threading.Thread(target=main_task)

        t1.start()
        t2.start()
        t2.join() # only the non-daemon thread is joined; once t2 finishes, t1 is killed automatically

      \end{pyconsole}
      \pcon{Daemon thread termination behaviour}{code:daemon_thread}

      As illustrated in \autoref{code:daemon_thread}, the daemon flag is set via the \textcode{.daemon} attribute prior to invoking \textcode{start()}; assigning it thereafter raises a \textcode{RuntimeError}. Once the non-daemon thread \textcode{t2} completes its iteration and \textcode{join()} returns, the Python runtime terminates the process entirely, forcibly halting the daemon thread \textcode{t1} regardless of its current state within the \textcode{while} loop.

      It is worth noting that daemon threads are deliberately not joined, as doing so would block the main thread indefinitely given their non-terminating nature. This distinguishes them from standard threads, where \textcode{join()} is used to ensure orderly completion.

    \end{core}
